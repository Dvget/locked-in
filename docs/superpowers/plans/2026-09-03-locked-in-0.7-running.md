# LOCKED IN 0.7 Running Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a reliable native iPhone running mode, custom training-type selection, lock-screen Live Activity, diagnostic data export, and the requested dashboard simplifications.

**Architecture:** A pure Swift tracking core classifies samples and calculates metrics independently of Core Location, SwiftData, ActivityKit, and SwiftUI. A session engine adapts Core Location to that core, while focused managers own audio, checkpointing, and the running Live Activity. Existing `RunRecord`, history, analytics, Polar sync, and backup flows are extended rather than duplicated.

**Tech Stack:** Swift 5, SwiftUI, SwiftData, Core Location, Core Motion, ActivityKit, AppIntents, AVFoundation, XcodeGen, XCTest/Swift Package Manager.

**Spec:** `docs/superpowers/specs/2026-09-03-locked-in-0.7-running-design.md`

## Global Constraints

- Marketing version is `0.7.0`; build number is `27`; deployment target remains iOS 17.
- Do not change the Cloudflare Worker or move Polar credentials/tokens into the app.
- Preserve existing manual and Polar runs; native runs use `source = "lockedIn"` and never deduplicate against Polar.
- Preserve existing strength, steps, weight, statistics, weekly report, Live Activity, and backup behavior.
- Keep the dark LOCKED IN design and avoid standard action sheets for mode selection.
- Do not add social, map, heart-rate, comparison-view, or interactive-chart features.
